# 改善提案（proposal_text.v1）

サイト評価の結果（補足の区画と外部データ）をもとに、既存サイトの改善提案を作る。

- 施策ごとに、対象箇所（ページURLと場所）・現状・問題点・改善内容・根拠の参照を書く。
- 「現状」は観測した事実だけを書く。推測を含める場合は「推測：」と明記する。
- 根拠の参照（evidenceRefs）には、評価項目ID（例：A1）または外部データのIDを1件以上書く。
- 問題の大きい順に並べ、priority を付ける。施策は多くても7件。
- 効果を数値で約束しない（「問い合わせが30%増える」などは書かない）。
- strengths には既存サイトの良い点を書く。提案で否定しないため。
- limitations には、取得できなかったページや推測を含む点を書く。
